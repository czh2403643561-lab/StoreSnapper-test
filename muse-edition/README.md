# StoreSnapper × Muse 对接说明

> 当前仅为对接说明；本目录尚无可安装的 Muse 定制版。

## 现有能力与数据边界

- **形态与源码：**StoreSnapper 是 Chrome Manifest V3 扩展。可安装源码在本项目的 `extension/`；GitHub 仓库为 `https://github.com/czh2403643561-lab/StoreSnapper-test`。Muse 定制版将单独放在本目录，原版继续独立使用。
- **输入：**目前由用户在 Temu 商品列表或 1688 商品浏览页点击图片放大镜，单张图启动 1688 搜图。后台目前只接受特定图片域名；尚不能导入 Excel/CSV 或直接接收 Muse 云端调用。
- **输出：**目前在 Chrome 侧栏显示相似货源及图片、标题、价格、起批量、销量、供应商名等可获得字段；没有本功能的批量导出文件，也没有可靠的供应商城市字段。缺失数据不能编造。
- **1688 登录态与账号信息：**依赖用户本机浏览器已登录的 1688。现有图搜代码没有向 Muse 或开发者服务器发送账号信息的逻辑；搜图令牌只用于当前请求签名，不写入日志或存储。图片与带有 1688 会话的请求会发往 1688 官方域名。Muse 定制版也不应接收 Cookie、令牌或密码。
- **验证：**遇到 1688 登录失效、滑块或安全验证时提示用户本人处理；扩展不破解或代过验证。

## 推荐的 Muse 独立版

书签脚本难以稳定复用扩展的后台权限、跨站图片读取及长批次恢复。本地服务或接口只有在 Muse 能调用用户电脑上的程序时才适合；云端 Muse 不能直接使用本机浏览器登录态。因此建议在本目录另做可安装的 Chrome 扩展，复用现有 1688 搜图链路，以批量导入和文件导出作为主要入口。它应有独立名称与入口，避免与原版同时安装时重复显示放大镜。

1. 导入 `.xlsx` 或 `.csv`，读取 `image` 列中的 TikTok 商品图片链接，并保留原品 `rank`、标题和原图链接。先确认实际表头、图片域名、图片链接是否会过期及浏览器能否访问。
2. 逐条搜图，设置可调整的请求间隔；记录每条的完成状态和结果，刷新后可续跑。遇到登录或验证即暂停，通知用户手动处理后继续，不自动跳过。
3. 每条原品导出前 **5** 个相似货源。输出 CSV、JSON 和可查看缩略图的 HTML；字段包括原品 rank、原标题、原图链接、候选图链接、1688 商品链接、候选标题、价格（元）、起批量、销量、供应商名、供应商城市、相似总数。没有候选时保留一行并标记 **「无」**；单个字段未由 1688 提供时标记 **「未提供」**。供应商城市需要先验证官方结果或详情页能否提供，再决定如何补采。
4. 只搜集和导出，不自动收藏或下单。第一轮不按地区或库存过滤；Muse 或用户根据原图与候选图、标题判断高度相似度和品牌/IP 风险。插件保留原始候选与链接，方便复核。
5. 先处理榜单前 20 条，核对字段和图片链接；确认后再处理全量 200 条。

## 请 Muse 回答

1. 你能读取用户上传的 CSV、JSON 和 HTML 并比较原图与候选图吗？是否必须主动调用接口？你能否在用户电脑上运行本地程序或控制本机浏览器？
2. 视觉相似、品牌/IP 剔除由你在收到导出文件后判断，还是需要扩展先自动筛选？若由你判断，请给出希望的输入文件格式。
3. 供应商城市如果 1688 官方搜图结果和商品页都未给出，接受「未提供」吗？

请同时提供榜单前 20 条的脱敏 `.xlsx` 或 `.csv` 样本，至少包含实际表头、`rank`、标题、`image` 链接。不要提供 1688 Cookie、令牌或密码。
